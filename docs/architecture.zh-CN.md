# 架构说明

**[English](./architecture.md)**

## 主链

```
用户输入
├─ 企业基本信息（公司、报告期间）        ┐
├─ 议题重要性评分（决定哪些议题进报告）   ├──────────────┐
├─ 定量指标（排放、用工、废弃物）         ┘              │
└─ 资料文件（制度、台账、证书）                          │
        │                                                │
        ▼                                                │
   File Agent            material.file_agent              │
   逐文件理解 → 可追溯 Dossier                            │
        │                                                │
        ▼                                                │
   Mapping Agent         material.mapping_agent           │
   按章节选材料，只选不写                                  │
        │                                                │
        ▼                                                ▼
   ┌─────────────────────────────────────────────────────────┐
   │ 受控证据集 —— 每个块只看见分配给它的事实                  │
   └─────────────────────────────────────────────────────────┘
        │
        ▼
   逐块生成正文        generation.blocks → generation.commit
        │                          ▲
        ▼                          │ 有阻断问题即退回，不出稿
   诊断闸              delivery.export_gate
        │
        ▼
   正式稿 + 审阅稿      delivery.docx.word / .review
```

人工逐段修订是可选环节，接在生成之后、诊断闸之前；诊断闸拦下的报告退回修订。

四类输入里只有企业基本信息必填，其余三类可以留空；系统按缺失事实调整写法，不编造内容补篇幅。

## 两个约束

### Agent 只选材料，不写正文

File Agent 读懂每份文件形成摘要，Mapping Agent 决定某个章节可以用哪几份材料。两者都**不产出
报告文字**。正文由另一条链路逐块生成，每个块只能看见分配给它的事实——靠结构保证不写企业没做过
的事，而不是在提示词里叮嘱模型。

### 诊断闸不调用模型

生成完不直接出稿。诊断层用代码检查完整性与一致性，有阻断级问题就拦下并指出位置。不调用模型，
所以同样的报告永远得到同样的判断。

## 知识包

一个包 = 一套准则 × 一种语言。包内承载：

- 议题清单与重要性判定方式
- 章节骨架与块级生成规格
- 准则条款与披露要求
- 定量指标目录
- 提示词与 Word 版式参数

当前三包：

| 包 | 准则 | 语言 | 重要性判定 |
|---|---|---|---|
| `sse_zh_hans` | 上海证券交易所 | 简体中文 | 双重重要性 |
| `hkex_zh_hant` | 香港联交所 | 繁體中文 | 财务重要性为主 |
| `hkex_en` | 香港联交所 | 英文 | 同上 |

换一套准则或一种语言＝换一个知识包，代码不分支。繁體与英文是两个独立的包，不是同一份内容的
转写。准则差异沉在数据层，加一个交易所、加一种语言不改生成链路。

## 章节层

写作是按章推进的，因此「章」是编排、编辑与交接的一等对象；但它**不是**新的正文容器：

- 一章＝一个顶层 H1 及其子树，身份沿用 `Section.key`。报告 schema 不变，存量报告无需迁移。
- 章批次按文档顺序逐节执行。每一节仍然通过单节路径的两个同一函数完成预留、生成与
  原子写回；章节层只增加顺序、进度、取消与逐节裁决。
- 一节失败不再丢弃整章：批次以 `partial` 结束，成功的节保持已提交状态，失败的节带稳定原因码。
- 每节开始前按库内 state 重建 Report，因此先写的节自然成为后写节的已披露事实。
- 章台账（`report_chapters`）只记生命周期与最近成功批次的指纹，不存正文；
  `chapter_generation_runs` 保证每章同时只有一个活动批次，并保存逐节进度。

章工作稿可离开网页去审阅：`export/chapter_workcopy.py` 把一章投影成 Markdown，交给
GenOffice 生成真正的 `.docx`，回读后产出块级变更提议。采纳提议走普通块编辑通道，
报告只有一条溯源链。正式交付物仍由整本渲染器产出并由确定性闸门判定；
工作稿是协作产物，不替代交付物。

## 运行时阶段

每次运行按登记的阶段落轨迹，出问题能定位到具体阶段而不是「生成失败了」。

| 阶段 id | 做什么 |
|---|---|
| `material.file_agent` | 逐份资料理解，产出可追溯摘要 |
| `material.image_agent` | 图片素材识别与题注 |
| `material.mapping_agent` | 按章节选材料 |
| `generation.blocks` | 逐块生成正文（支柱块、结论块分批） |
| `generation.chapter` | 跑完一个章批次：逐节、按库内 state 重建 Report |
| `generation.chapter.section` | 章批次中的一节（预留 → 生成 → 原子写回） |
| `generation.row` | 表格逐行生成 |
| `generation.commit` | 写回结构化报告 |
| `delivery.export_gate` | 确定性诊断，有阻断问题即拦下 |
| `delivery.render` | 渲染 Word |
| `delivery.docx.word` / `.review` | 正式稿与审阅稿两份产物 |

阶段词汇表由 `backend/src/sustainability_desk/observability/registry.py` 聚合，阶段常量与
实现同址声明，导入即登记、冲突即抛错。
